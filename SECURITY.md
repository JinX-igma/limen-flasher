# Security policy

Do not report real device tokens, Wi-Fi passwords, gateway CA private
keys, or device dumps in a public issue.

This firmware never holds a real upstream LLM API key — only a
per-device bearer token issued by your [`limen-gateway`](https://github.com/JinX-igma/limen-gateway)
instance, which your gateway operator can revoke at any time without
affecting any other device or the real upstream credential.

A device token stored in ESP32 NVS can still be extracted by an
attacker with physical access to the board. If that happens, revoke
just that device (`DELETE /admin/devices/{id}` or
`scripts/manage-devices.py revoke <id>` on the gateway) — this does not
require rotating any shared credential or touching other devices.

Enable ESP32 secure boot and flash encryption when your hardware
lifecycle supports them; this project does not do so by default.

The `allow_insecure_tls` captive-portal option disables certificate
validation entirely (`WiFiClientSecure::setInsecure()`). It exists only
for same-LAN demo gateways whose certificate you have not yet pinned.
Never enable it for an internet-facing gateway, and never ship it
enabled by default — it defaults off and requires an explicit,
in-portal opt-in with an inline warning.

`include/gateway_root_ca.h` (generated by `scripts/embed_gateway_ca.py`)
contains your gateway's CA certificate and is gitignored. It is not
secret by itself (it's a public certificate, not a private key), but it
is deployment-specific and should not be committed — CI will fail the
build if it is.
